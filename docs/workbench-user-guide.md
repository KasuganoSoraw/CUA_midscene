# CUA 工作台使用指南

CUA 工作台（页面名称为“桌面任务中心”）用于把人工演示的桌面操作整理为可复用任务，并完成检查、修改和调试。它在本机浏览器中打开，任务和运行产物保存在本地数据目录。

本文面向任务录制者和维护者。通过 GDEClaw 等宿主打开工作台时，直接从“流程录制”开始；独立使用源码时，先完成“环境准备与启动”。宿主外围界面不属于本文范围。

通过 GDEClaw 使用工作台的日常操作和用户流程，见 [CUA 工作台操作指南](./workbench-end-user-guide.md)。

## 1. 使用流程

```text
准备目标应用 → 录制操作 → 生成任务 → 检查并保存步骤 → 调试运行 → 查看报告
                                         ↑                         │
                                         └──── 根据实际结果调整 ────┘
```

工作台提供三个主要页签：

| 页签 | 用途 |
| --- | --- |
| 流程录制 | 选择屏幕、采集操作，或使用已有录制生成任务 |
| 任务检查 | 查看截图，编辑动作、运行参数和定位参考图，保存任务 |
| 任务调试 | 选择运行方式和本次参数，执行任务并查看结果报告 |

任务按“场景 → 任务”组织。例如，场景 `expense` 下可以包含 `create-application`、`query-application` 等任务。空数据目录没有内置任务，可从一次录制开始。

## 2. 环境准备与启动

### 2.1 使用前确认

- 在可交互的 Windows 桌面中使用；录制器支持 Windows 10/11。
- 目标应用已安装，所需账号、网络和权限可用。
- 录制处理和执行所需的模型服务已由维护人员配置。
- 不要同时运行其他会操作同一桌面的自动化任务。

通过宿主使用时，由宿主准备运行环境并提供工作台入口。以下命令仅适用于源码开发环境。

### 2.2 源码环境首次准备

需要 Python 3.11+、uv，以及满足项目要求的 Node.js（`>=20.18.1`，可使用 `22.18.0`）。在仓库根目录执行：

```powershell
uv sync --locked --directory agent
uv sync --locked --directory record
uv sync --locked --directory recorder

cd execution
npm.cmd ci
npm.cmd run build
```

`npm.cmd` 是 Windows 的 npm 命令入口，可以避免 PowerShell 将 `npm` 解析为受执行策略限制的 `npm.ps1`；在其他终端中也可使用 `npm`。

### 2.3 配置本地目录与模型

完整配置项以仓库根 [`.env.example`](../.env.example) 为准。首次使用时，将它复制为同目录下的 `.env.local` 并填写实际值；已有 `.env.local` 时直接编辑，不要覆盖。

两个目录的用途不同：

| 配置项 | 用途 | 示例 |
| --- | --- | --- |
| `CUA_DATA_ROOT` | 已生成的场景、任务、运行结果与报告 | `E:/CUAData` |
| `CUA_RECORDINGS_ROOT` | 原始录制集合，新录制也写入这里 | `E:/CUARecordings` |

使用本机绝对路径，并确保目录存在且具有所需的读写权限。`CUA_RECORDINGS_ROOT` 应指向所有录制目录的父目录，而不是某一次录制或其 `inputs` 目录。

模型配置由环境维护人员根据实际服务填写，主要包括 `MIDSCENE_MODEL_BASE_URL`、`MIDSCENE_MODEL_NAME`、`MIDSCENE_MODEL_API_KEY` 和适配的 `MIDSCENE_MODEL_FAMILY`。录制处理可使用独立的 `OPENAI_*` 配置；未设置时读取相应的 `MIDSCENE_MODEL_*`。不要将真实密钥提交到仓库或写入任务说明。

源码环境从进程环境、仓库根 `.env.local`、仓库根 `.env` 依次读取配置，进程环境优先。修改环境文件后，需要停止已有服务并重新启动。产品宿主通过进程环境提供配置，不依赖源码环境文件。

### 2.4 打开与关闭工作台

在 `execution` 目录执行：

```powershell
npm.cmd run cua -- review
```

命令会启动本地服务并尝试打开系统浏览器。也可以指定数据目录且不自动打开浏览器：

```powershell
npm.cmd run cua -- review --data-root E:/CUAData --no-open
```

`--no-open` 只关闭自动打开浏览器的行为，不关闭服务。使用终端打印的地址访问页面，默认地址为 `http://127.0.0.1:47831/`。`--data-root` 优先于环境中的数据目录配置。

重复启动时，符合服务身份要求的现有实例会被复用；不同数据目录、不可兼容的开发模式或其他程序占用端口时会提示错误，不会自动换端口。普通使用不需要 `--dev`。

关闭浏览器页签不等于停止服务或正在执行的操作。独立启动时，保留启动服务的终端；结束使用前先停止录制或任务，再在原启动终端按 `Ctrl+C`。通过宿主打开时，服务生命周期由宿主管理。

## 3. 流程录制：从演示创建任务

### 3.1 录制前准备

1. 打开目标应用并完成登录，确认所需页面能够访问。
2. 明确任务的初始界面和结束状态，每次尽量只录制一个完整业务流程。
3. 使用测试账号与测试数据；注意视频、截图和键鼠日志可能包含敏感信息。
4. 确认关键操作都发生在将要选择的屏幕上。

录制器采集物理键鼠事件，不支持暂停、音频、安全桌面、UAC 或锁屏操作，也不还原中文输入法最终提交的文本。

### 3.2 开始与结束录制

1. 进入“流程录制”，页面自动检测屏幕并默认选择主屏。
2. 点击目标屏幕卡片；显示器发生变化时点击“重新检测”。
3. 点击“准备录制”，等待页面显示录制已准备。
4. 切换到目标应用，按 `Ctrl+Shift+F9` 开始录制。
5. 按实际业务顺序操作，避免插入与任务无关的窗口切换和点击。
6. 完成后再次按 `Ctrl+Shift+F9` 停止，等待录制保存完成。
7. 返回工作台，在录制列表中选择刚才的录制；必要时点击刷新按钮。

“准备录制”不会立即开始采集。准备阶段可取消；录制过程中可使用“紧急停止”结束采集。停止后先等待保存完成，不要直接关闭启动终端。

### 3.3 使用已有录制

将兼容的录制放在 `CUA_RECORDINGS_ROOT` 的一级子目录中，结构如下：

```text
<CUA_RECORDINGS_ROOT>/
└── Recording_20261016_100000/
    └── inputs/
        ├── Recording_20261016_100000.mp4
        └── Recording_20261016_100000.txt
```

每个 `inputs/` 目录需要恰好一个 MP4 和一个事件日志文件（`.txt`、`.log` 或 `.json`）；日志内容必须与录制处理器兼容，并非任意文本文件。缺少文件或存在多个候选文件时，列表会展示原因，暂不能生成任务。

视频和日志以文件卡片展示。点击卡片或录制路径可打开本机对应目录，再用本机应用查看；工作台不内嵌播放视频或展示完整日志。

### 3.4 生成任务

选中可用录制后填写：

| 字段 | 填写方法 |
| --- | --- |
| 任务名称 | 新任务的目录标识，例如 `create-application`，不能与同一场景下的已有任务重复 |
| 场景 | 从下拉列表选择已有场景，或输入新场景标识，例如 `expense` |
| 任务描述（可选） | 说明业务目标，例如“填写并提交一份报销申请” |

场景和任务标识不要包含 `/`、`\` 等路径分隔符，建议使用简短、稳定的字母、数字和连字符组合。

点击“生成任务”后，右侧显示正在生成。此时可以切换页签，返回或刷新页面后会读取服务中保留的生成状态；不要停止或重启工作台服务。页面不展示逐行处理日志，也不提供精确完成百分比。

生成成功后点击“查看任务详情”，进入任务检查。生成过程会创建任务配置和截图等资产，不会执行录制中的业务操作。已有任务不会被覆盖；同一份录制可用不同任务名称再次创建。

任务描述用于任务说明，不会替代对实际步骤的逐项检查。生成失败时，根据页面提示检查录制文件、模型配置和服务环境，再决定是否重新生成。

### 3.5 删除原始录制

点击“删除录制”并确认后，将永久删除该录制目录中的视频、日志及其他文件，已经生成的任务不会被删除。活动录制期间不可删除。需要保留教学证据时，应先单独备份。

## 4. 任务检查：核对和编辑步骤

### 4.1 选择任务与查看截图

左侧按场景展示任务，可用搜索框筛选。选择任务后，中间展示步骤列表，右侧展示当前步骤的截图和动作配置。

- “完整截图”：查看动作发生时的整体页面。
- “局部截图”：查看目标附近的细节，通常作为默认视图。
- “定位参考图”：供单击、双击动作配置执行时的外观参考。

没有对应截图的步骤显示占位图，不借用其他步骤的截图。手动新增步骤通常没有独立录制截图。

先核对操作顺序、目标和输入内容，再检查等待条件及定位参考图。日常编辑使用表单即可，不需要修改 JSON。

### 4.2 配置动作

| 动作类型 | 主要配置 | 示例 |
| --- | --- | --- |
| 单击鼠标 / 双击鼠标 | 目标描述 | “申请表底部、取消按钮右侧的蓝色‘提交’按钮” |
| 输入文本 | 输入框位置、输入方式、固定值或运行参数 | “联系人区域中，‘邮箱’标签右侧的输入框” |
| 按键 | 按键名称或组合键 | `Enter`、`Escape`、`Control+A` |
| 等待 | 等待触发条件、等待时长 | “页面出现‘提交成功’提示”，最长等待 `15000` 毫秒 |

描述目标时，优先使用可见文字、所在区域和相对位置，避免只写“这里”“这个按钮”。相似控件较多时，应明确属于哪一行、哪一个面板或哪个标签附近。

“动作前等待”是执行该动作前的固定暂停，单位为毫秒；“等待”动作的“等待时长”是条件满足的最长时间，不是固定暂停。`1000` 毫秒等于 `1` 秒。页面加载速度不稳定时，优先描述可观察的等待条件。

### 4.3 配置输入文本

“输入方式”有两种：

- “替换原内容”：使用本次文本替换输入框中的内容。
- “追加到末尾”：在已有内容后继续输入。

通过“允许运行时输入”右侧开关控制是否把文本作为运行参数：

| 开关状态 | 编辑内容 | 运行行为 |
| --- | --- | --- |
| 开启 | 输入标签、录制默认值、可选参数说明 | 调试页展示该参数，可填写本次值，初始使用默认值 |
| 关闭 | 固定输入值 | 执行时使用保存的固定文本，不展示为运行参数 |

“输入标签”是给使用者看的名称，例如“申请单号”；它不是实际输入内容。“录制默认值”才是参数的默认文本。修改标签不会改变目标输入框的位置描述。

按步骤运行中的文本输入使用物理键盘事件，当前支持 ASCII 字符，不通过剪贴板粘贴；中文等非 ASCII 内容不属于该输入动作的直接支持范围。

### 4.4 使用定位参考图

定位参考图帮助模型识别目标外观，适合文字较少、外观有辨识度的图标等目标。执行时仍结合目标描述和当前屏幕定位，不是录制坐标回放或像素模板匹配。

1. 选择单击或双击步骤，切换到“定位参考图”。
2. 有可用图片时，检查内容并通过“启用定位参考图”开关控制是否使用。
3. 没有图片时点击“点击上传”；需要更换时点击“点击更换图片”。
4. 上传后核对图片及开关状态，点击页面顶部“保存”。

上传支持 PNG、JPEG、WebP，单张不超过 5 MB、1600 万像素，边长不超过 6000 像素；不支持 SVG 或多帧图片。建议选择只包含目标及必要上下文、不带红叉等点击标记的清晰局部图。

输入文本、按键和等待动作不提供定位参考图上传。停用图片不会删除图片文件，更换图片也不会覆盖原始录制截图；上传成功不等于任务已保存。

### 4.5 新增、排序和删除步骤

- 点击“新增动作”，在当前选中步骤之后插入一个单击动作，再设置所需类型和内容。
- 拖动步骤行调整执行顺序。
- 点击步骤右侧删除图标移除步骤；只剩一个步骤时不能删除。

删除步骤和切换动作类型直接生效到草稿，不弹出二次确认。切换动作类型会按所选类型初始化表单；操作前注意保留仍需使用的内容。

### 4.6 草稿、保存与冲突

表单修改会联动任务草稿，并自动保存在当前浏览器中。自动保存草稿不等于写入磁盘上的任务配置：

- 点击“保存”：校验并写入任务，后续执行使用保存后的配置。
- 点击“保存并运行”：先保存，再切换到任务调试页；仍需在那里点击“准备运行”。没有待保存修改时，该按钮显示“运行此任务”。
- 切换任务、页签或刷新：可恢复当前浏览器中已存储的草稿，但不能把浏览器草稿当作长期备份。

浏览器禁用存储、清理站点数据、更换浏览器或更换访问端口，都可能影响草稿恢复。出现自动保存失败提示时，应及时完成显式保存。

Agent、其他页面或编辑器在外部修改任务后，保存可能提示冲突；工作台不会直接覆盖外部内容。先记录需要保留的修改，再点击“重新载入”并确认，载入磁盘任务后重新检查。重新载入会丢弃该任务的本地草稿。

“删除任务”需要在页面内确认，将永久删除该任务目录及其中配置和截图；场景、其他任务和原始录制不受影响。

## 5. 任务调试：执行与检查结果

### 5.1 准备运行

1. 确认任务检查中的修改已经保存。
2. 进入“任务调试”，选择场景和任务。
3. 选择运行方式：
   - “按步骤运行”：依次执行任务中保存的动作，适合检查录制步骤。
   - “自适应运行”：依据任务目标及步骤信息整体规划并执行，不保证与录制动作一一对应。
4. 填写“本次运行参数”。这些值只用于本次运行，不会回写任务的默认值。
5. 将目标应用恢复到任务预期的初始状态，包括登录、窗口、页面和必要数据。
6. 点击“准备运行”，在 **5 秒倒计时内**切换到目标应用。

运行会直接操作当前桌面。执行期间不要手动移动鼠标、输入键盘、切换窗口、启动录制或并发运行其他桌面任务。保持目标桌面可见，不要锁屏或进入 UAC 安全桌面。

### 5.2 停止任务

倒计时期间可以“取消准备”；运行期间可以“停止任务”。等待状态变为已停止后再操作桌面。

停止不是业务回滚。已经点击、输入或提交的操作可能保留在目标系统中；重新运行前必须确认业务状态，避免重复提交。

### 5.3 阅读结果与报告

| 结果 | 含义与下一步 |
| --- | --- |
| 执行完成 | 执行器完成本次运行；打开报告并核对目标系统中的实际结果 |
| 运行未完成或具体错误提示 | 查看简短原因，结合报告定位问题；必要时展开“技术详情” |
| 已停止运行 | 本次运行被主动停止；检查目标应用保留的操作 |
| 暂时无法获取运行状态 | 本地服务连接异常；先确认服务和目标桌面状态，不要据此认定任务已停止 |

存在有效报告时，可点击“查看执行报告”在新页签打开。报告可用于核对执行动作、截图及错误信息；若没有可用报告，页面会明确提示。任务尚未启动或报告未生成时，不一定有报告链接。

失败说明依据明确错误信号展示，不调用 Agent 推测根因，也不自动重试、切换模式或修改任务。不能确定原因时，页面保留通用说明，原始错误位于折叠的“技术详情”中。

执行完成不代表业务结果一定正确。首次调试至少核对目标记录、关键字段和最终页面；失败后应先查明已执行到的状态，再决定修改任务或重新运行。

## 6. 本地数据与备份

```text
<CUA_RECORDINGS_ROOT>/
└── <录制目录>/inputs/          # 原始视频和事件日志

<CUA_DATA_ROOT>/
├── projects/<场景>/
│   ├── scene.json            # 场景信息
│   └── <任务>/
│       ├── task.yaml         # 保存后的执行步骤
│       ├── task.json         # 任务信息、输入定义和默认值
│       └── source/           # trace、截图、定位参考图等资产
└── runs/<run-id>/             # 本次执行快照、结果和报告
```

备份任务时，应保存完整场景目录（含 `scene.json` 和所需任务），或直接备份整个 `projects/`。不要只复制 `task.yaml`，否则可能缺少场景信息、输入定义和图片。原始录制独立保存，任务目录不包含原始视频与事件日志的完整副本。

运行历史会按空间策略自动清理，默认超过 5 GiB 后从较旧运行清理至约 4 GiB，并保护当前、活动及近期运行。任务与原始录制不在该清理范围内。需要长期保存的报告、截图或输入快照，应另行归档；清理后原报告链接会失效。具体配置见 [运行历史空间管理](../execution/README.md#运行历史空间管理)。

视频、截图、任务默认值、运行输入及报告都可能包含业务数据。技术提示中的脱敏不等于所有资产都已脱敏；共享或上传前，应检查并遵守所在环境的数据安全要求。

## 7. 常见问题

| 问题 | 排查方法 |
| --- | --- |
| 提示未配置录制目录 | 在仓库根 `.env.local` 或宿主进程环境中设置 `CUA_RECORDINGS_ROOT`；确认是存在的绝对目录，重启服务。无需在网页中选择路径 |
| 任务列表为空 | 首次使用属正常情况；检查 `CUA_DATA_ROOT`，从“流程录制”生成首个任务。已有任务应位于其 `projects` 下 |
| 录制显示“需检查”，无法生成 | 查看文件错误；确认一级录制目录下的 `inputs/` 中恰好有一个 MP4 和一个兼容日志 |
| 无法检测屏幕或准备录制 | 确认在交互式 Windows 桌面运行，检查 Python 录制环境；源码环境可在 `recorder` 中执行 `uv run cua-recorder doctor` |
| 生成耗时较长 | 页面只提供生成中状态；可以切换页签，但保持服务运行。失败后检查录制、模型和网络，不重复连续提交 |
| 修改后执行仍使用旧内容 | 检查是否只保存了浏览器草稿；先在“任务检查”点击“保存”，再进入调试页重新选择目标任务 |
| 没有本次运行参数 | 只有开启“允许运行时输入”并保存的输入步骤会展示；固定输入值不会出现在参数区 |
| 修改环境文件后没有生效 | 先停止旧服务再启动；重复启动可能只复用已有服务，且进程环境的值优先于环境文件 |
| 端口 `47831` 被占用 | 确认是否为使用其他数据目录或开发模式的工作台，或其他程序；由维护人员停止对应实例，不要随意结束未知进程 |
| 执行失败或超时 | 先查看报告和技术详情，检查目标初始界面、目标描述、等待条件以及模型服务；重新运行前确认没有重复提交风险 |
| 报告不存在或无法打开 | 可能尚未生成、文件已清理或服务已关闭；确认服务和运行目录。需要长期保留时提前归档 |

## 8. 开发调试入口与参考

开发人员可在 `execution` 中执行：

```powershell
npm.cmd run cua -- review --dev
```

该模式增加“开发调试”页签和高级任务数据等诊断信息，不是日常录制与复核的必要条件。开发调试中的 Agent 调用是独立任务，不继承前一次调用的会话；涉及真实桌面操作时仍须串行执行。
