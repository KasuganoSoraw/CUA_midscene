# CUA 工作台操作指南

本文面向从 GDEClaw 打开 CUA 工作台的使用者。你可以在这里演示一段桌面操作，将它整理成任务，检查操作步骤，再让系统试运行并核对结果。

工作台的使用不需要编写代码或修改配置文件。

## 1. 先认识三个页签

| 页签 | 它负责什么 | 什么时候使用 |
| --- | --- | --- |
| **流程录制** | 记录你如何操作，并从录制中生成任务 | 教系统一个新流程，或用已有录制创建任务时 |
| **任务检查** | 查看和修改系统整理出的步骤 | 生成任务后，或需要调整已有任务时 |
| **任务调试** | 让系统实际操作桌面，检查任务是否符合预期 | 步骤检查并保存后，需要试运行时 |

可以把它们理解为：**我来演示 → 一起核对 → 系统试做**。

“场景”用于给任务分组，“任务”是一项具体工作。例如，“订单管理”场景下可以有“订单查询”“订单信息填写”等任务。

## 2. 第一次使用：完整走一遍

以“输入订单号并查询订单”为例：

```text
打开订单查询页面
       ↓
流程录制：演示输入订单号、点击查询
       ↓
生成任务：把录制整理成可编辑的操作步骤
       ↓
任务检查：核对步骤，把订单号设为运行时输入
       ↓
保存任务
       ↓
任务调试：填写另一个订单号，让系统试运行
       ↓
查看实际查询结果和执行报告
```

如果已经有录制，可以直接从“选择录制并生成任务”开始；如果已经有任务，可以从“任务检查”或“任务调试”开始，不必每次重新录制。

## 3. 流程录制：把操作演示给系统

### 3.1 录制前做什么

先打开目标应用，完成登录，并停留在流程开始的位置。例如，录制订单查询前，先进入订单查询页面。

一次录制尽量只演示一件完整的事情，明确从哪里开始、到哪里结束。优先使用测试数据，避免录入真实密码或其他敏感信息；录制会留下屏幕画面和键鼠操作记录。

### 3.2 如何录制

1. 在 GDEClaw 中打开工作台，进入“流程录制”。
2. 选择目标应用所在的屏幕。页面会展示屏幕预览；屏幕发生变化时可点击“重新检测”。
3. 点击“准备录制”。此时只是就绪，还没有开始记录。
4. 切换到目标应用，点击桌面悬浮条的“开始录制”，或按 **`Ctrl+Shift+F9`**。悬浮条显示录制计时和停止按钮。
5. 按正常业务顺序完成操作，尽量不要夹杂无关点击或窗口切换。
6. 点击悬浮条的“停止录制”，或再按一次 **`Ctrl+Shift+F9`**，等待保存完成。准备阶段可通过悬浮条“取消”退出。
7. 返回工作台，在录制列表中选择这次录制。

准备阶段不想录了，可以取消；录制过程中需要提前结束，可以点击“紧急停止”。一次录制中的操作应尽量都在所选屏幕内完成。

### 3.3 录制完成，为什么还要“生成任务”？

**录制是“记下你做了什么”，生成任务是“把这次演示整理成系统能够执行的步骤”。**

录制留下的是视频和操作记录。点击“生成任务”后，系统会分析这些记录，整理出单击、输入文本、按键、等待等步骤，并提供截图供你核对。

因此：

- 录制结束，不代表已经创建了可运行任务。
- 生成任务不会再操作一次目标应用，也不会提交录制中的业务。
- 生成成功不代表每一步都已理解准确，仍需进入“任务检查”。

### 3.4 选择录制并生成任务

在录制列表中选中一条记录，查看右侧的视频和操作记录卡片。点击卡片可打开对应录制所在的文件夹，再查看原始文件；卡片本身不是视频播放器。

填写以下信息：

| 信息 | 怎样填写 | 订单查询示例 |
| --- | --- | --- |
| 任务名称 | 用于识别这项具体工作，避免与同一场景内的任务重名 | 订单查询 |
| 场景 | 选择已有分组，或输入新的分组名称 | 订单管理 |
| 任务描述（可选） | 简要说明最终想完成什么 | 根据订单号查询并展示订单详情 |

点击“生成任务”，右侧会显示正在生成。可以切换工作台页签，回来后继续查看状态，不需要一直停留在原页面。生成可能需要一些时间，不要连续重复提交，也不要退出 GDEClaw 或结束工作台。

成功后点击“查看任务详情”，进入“任务检查”。如果生成失败，先查看提示；无法自行处理时，请联系维护人员，不需要自己修改程序或配置。

同一条录制可以生成不同名称的任务，已有任务不会被覆盖。任务描述是对目标的说明，不能代替准确的演示和步骤检查。

## 4. 任务检查：确认系统有没有理解对

### 4.1 页面怎么看

- **左侧：场景与任务。** 找到想检查的任务，也可以输入关键词搜索。
- **中间：任务步骤。** 按执行顺序展示每一步，点击即可查看详情。
- **右侧：截图与动作配置。** 对照当时的画面，核对系统将要做的事情。

建议从第一步开始，依次检查：目标是否找对、输入内容是否合适、顺序是否正确、是否需要等待页面加载。

### 4.2 三种图片有什么区别

| 图片 | 主要用途 |
| --- | --- |
| 完整截图 | 给人看整体页面，了解这一步发生在哪里 |
| 局部截图 | 给人看目标附近的细节，帮助描述和核对操作对象 |
| 定位参考图 | 给系统提供目标的外观参考，辅助运行时寻找目标 |

某一步没有录制截图时会显示占位图，例如手动新增的步骤。这不表示它会使用上一张截图，也不妨碍你填写动作内容。

### 4.3 每种动作应该检查什么

| 动作 | 检查重点 |
| --- | --- |
| 单击鼠标 / 双击鼠标 | 要点击哪个对象，描述是否足以区分相似按钮或图标 |
| 输入文本 | 在哪个输入框输入，是替换还是追加，文本是否每次都相同 |
| 按键 | 按哪个键或组合键，例如 `Enter`、`Control+A` |
| 等待 | 等页面出现什么状态，以及最多等多久 |

目标描述尽量包含可见文字和所在位置。例如，“查询条件区域中，‘订单号’右侧的输入框”，比“第一个框”更容易理解。

“动作前等待”表示先固定停一段时间再做这一步；“等待”动作则是在等待某个状态出现。界面上的时间单位是毫秒，`1000` 毫秒等于 `1` 秒。

例如，等待条件填写“查询结果表格出现”，等待时长填写 `10000`，表示最多等 10 秒，条件提前满足就继续，不是固定停满 10 秒。

### 4.4 哪些文本需要每次重新填写

在“输入文本”动作中，“允许运行时输入”开关决定这段文本能否在每次运行前更换。

- **开启：适合订单号、查询关键词等每次可能不同的内容。** 填写“输入标签”，让使用者知道要填什么；“录制默认值”作为运行前的初始值，还可以填写参数说明。
- **关闭：适合每次都相同的内容。** 在“固定输入值”中填写文本，执行时直接使用它。

例如，将订单号步骤的开关打开，输入标签设为“订单号”。以后在“任务调试”中就会出现“订单号”输入框，无需为了换一个订单号而修改整项任务。

“输入标签”只是显示名称，不是要输入到目标应用的内容。“输入方式”中的“替换原内容”会替换输入框已有文本，“追加到末尾”则保留原内容并继续输入。

按步骤运行的文本输入目前支持英文字母、数字和常见英文符号等字符，不支持直接输入中文。需要中文输入的业务，请先与维护人员确认适用方式。

### 4.5 什么时候使用定位参考图

当目标是没有文字的小图标，或仅靠文字不容易说明外观时，可以使用定位参考图。

选择单击或双击步骤，切换到“定位参考图”，检查已有图片，也可以点击上传或更换图片，再通过“启用定位参考图”开关决定是否使用。选图时尽量只保留目标和必要的周边内容，不要带红叉等点击标记。支持 PNG、JPEG、WebP，单张不超过 5 MB。

定位参考图只是辅助，系统仍会结合当前画面和目标描述寻找对象，不是照着录制时的固定坐标点击。输入文本、按键和等待动作不提供此功能。上传或更换后，仍需保存任务。

### 4.6 调整步骤与保存

- **新增动作：** 在选中的步骤后增加一步，再设置动作类型和内容。
- **拖动排序：** 拖动步骤行，调整执行先后顺序。
- **删除步骤：** 点击步骤右侧的删除图标。删除步骤不再弹出确认，请先确认选中的步骤。
- **修改动作类型：** 切换为另一种动作后，需要检查并重新填写相应内容。

编辑会自动保留为当前浏览器中的草稿，但**完成检查后，仍要点击顶部“保存”**，修改才会正式用于任务执行。

“保存并运行”会先保存修改，再进入“任务调试”，不会立刻接管桌面；你仍有机会检查本次参数和目标页面。没有待保存修改时，按钮显示“运行此任务”。

## 5. 任务调试：让系统试做一次

### 5.1 选择任务和运行方式

进入“任务调试”，确认场景与任务，然后选择运行方式：

- **按步骤运行：** 按任务中的步骤依次执行。首次检查录制结果时，建议先使用这种方式。
- **自适应运行：** 根据任务目标及步骤信息整体规划并执行，实际动作不一定与录制逐步一致。

有“调试任务参数”时，填写这一次要使用的值。例如，输入另一个需要查询的订单号。这些值只影响本次运行，不会修改任务保存的默认值。

### 5.2 复制指令到 GDEClaw

需要从 GDEClaw 对话中调用这个任务时，在“复制以下指令到对话即可运行任务”区域点击复制按钮，再自行粘贴到 GDEClaw 对话框发送。指令包含电脑操控插件、当前任务名称和所选运行方式。

复制只把文字放入剪贴板，不会发送消息或立即运行。它不包含本页临时填写的调试参数；需要使用其他输入值时，请在对话中一并说明。若自动复制失败，可选中指令文字手动复制。

### 5.3 准备桌面，再开始

1. 确认目标应用已登录，并回到任务要求的起始页面。
2. 确认本次操作可以安全执行，尤其是提交、删除等可能产生实际业务影响的步骤。
3. 点击“调试任务”，在 **5 秒倒计时内**切换到目标应用。
4. 系统开始操作后，不要手动使用鼠标键盘、切换窗口或同时启动另一项桌面任务，也不要锁屏。

系统操作的是当前桌面，不是一个与你的操作互不影响的后台副本。

倒计时期间可以“取消准备”。运行中需要中断时，可以“停止任务”，等待页面显示已停止。**停止不会撤销已经完成的操作**，已经填写或提交的内容可能仍然存在。

### 5.4 怎样判断这次是否成功

运行结束后，查看结果提示；存在报告时，点击“查看执行报告”，结合执行过程、截图和目标应用中的实际结果进行检查。

| 页面提示 | 应该怎样理解 |
| --- | --- |
| 执行完成 | 系统已结束本次执行，还需要你确认业务结果是否符合预期 |
| 运行未完成或具体失败提示 | 本次未能完成，先查看提示和报告，必要时展开“技术详情” |
| 已停止运行 | 任务已被中断，检查哪些操作已经发生 |
| 没有可用的执行报告 | 本次没有生成可查看的报告，不代表任务成功或失败的原因已确定 |

订单查询示例中，应核对“是否打开了正确订单”“订单号是否一致”，而不只是看到“执行完成”。

失败后不会自动重试。先确认目标应用现在的状态，再决定回到“任务检查”调整步骤，或恢复起始页面重新试运行。涉及提交业务时，尤其要避免重复提交。

## 6. 日常使用可以走哪些路径

- **教一个新任务：** 流程录制 → 生成任务 → 任务检查 → 保存 → 任务调试。
- **继续检查已有任务：** 在任务检查中找到它 → 编辑 → 保存，不必重新录制。
- **只更换本次输入：** 在任务调试中选择已有任务 → 填写本次运行参数 → 点击“调试任务”。
- **试运行发现不准确：** 查看报告 → 确认已发生的操作 → 回到任务检查调整 → 保存 → 恢复起始页面后再次调试。

## 7. 常见疑问

**录完后，我还需要手工把视频里的步骤抄出来吗？**

不需要。点击“生成任务”后由系统整理，你负责核对和调整，而不是从头编写步骤。

**任务正在生成，可以去做别的事吗？**

可以切换工作台页签，也可以处理其他事情；生成过程不会控制桌面。请保持 GDEClaw 和工作台运行，完成后回来查看。任务实际运行时则不要操作同一桌面。

**修改已经自动保留，为什么还有“保存”？**

自动保留用于防止误刷新等操作丢失草稿；“保存”表示把修改正式写入任务。不要把草稿当作长期备份，结束编辑前应点击“保存”。

**页面提示任务已在其他位置更新，怎么办？**

可能有人或系统同时修改了任务。先记录自己需要保留的内容，再“重新载入”查看已保存内容；重新载入会丢弃当前草稿。无法判断如何合并时，请联系维护人员。

**可以删掉原始录制吗？会把任务一起删掉吗？**

“删除录制”只删除该份原始录制，不删除已经生成的任务；但视频和操作记录会永久删除。“删除任务”则删除对应任务及截图，不会删除其他任务或原始录制。这两类删除都需要确认。

**列表为空、录制不可用，或页面显示环境未就绪，怎么办？**

第一次使用时没有任务是正常的，可以先录制。已有数据未显示，或遇到录制、生成、运行环境相关提示时，把页面提示提供给维护人员，不需要自己配置环境。

**任务失败、报告打不开，或运行状态无法获取，怎么办？**

先保留提示并查看目标应用，不能仅凭页面断开就认定任务已停止。不要立即重复运行；有报告时先查看报告，仍无法判断时联系维护人员。报告并非永久保存，需要留存时应及时归档。

关闭工作台页面不会撤销已经发生的操作，也不应当作“停止任务”的方法。离开前先确认录制或任务已经结束；分享录制、截图和报告前，注意其中是否包含敏感信息。
