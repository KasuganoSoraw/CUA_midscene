## Context

review service 已同时投影两类信息：`task.json.source` 对应 processed log 中的 `screenshot_reference` 表示录制阶段存在一张可用图片，`task.yaml` 中的 `locate.images` 表示执行时已经绑定的定位资产。当前 Vue 页面能展示两种状态，step editor 也能无损解析和重建 `locate.images`，但普通界面只提示用户进入高级 JSON 修改。

录制器为一个 click/doubleClick 步骤最多生成一张目标居中的 `96×96` PNG。Midscene 协议仍将 `locate.images` 定义为数组，因此页面需要在“单图产品交互”和“多图协议兼容”之间保持明确边界。

## Goals / Non-Goals

**Goals:**

- 使用“定位参考图”作为统一的人类可读名称，并解释它提供目标外观而非固定坐标。
- 允许用户在普通界面将当前步骤的录制定位参考图加入或移出执行定位。
- 让绑定变化立即反映到语义表单生成的 Flow、高级 JSON 和变更对比，并继续通过现有确认保存流程写盘。
- 保持 builtin 只读边界、标准动作边界以及既有多图 YAML 的无损往返。

**Non-Goals:**

- 不允许选择其他文件、上传图片、编辑裁剪范围或替换 reference patch。
- 不修改录制器生成规则、review HTTP API、Midscene YAML 协议或执行器。
- 不为多张 `locate.images` 设计普通用户的增删排序界面。
- 不改变页面默认优先展示局部录制证据的规则。

## Decisions

### 1. 统一使用“定位参考图”，不展示单图序号

证据页签、状态摘要和帮助文案统一使用“定位参考图”。当普通界面只展示一张图片时，页签不附加数量，图片卡片也不显示“目标小图 1”或技术生成名称。

帮助文案明确说明：图片用于告诉 Midscene 目标“长什么样”，执行时仍结合当前页面和目标描述进行视觉定位，不表示固定点击坐标。相比“目标小图”，“定位参考图”直接表达用途；相比“定位图”，它减少固定坐标或模板匹配的误解。

### 2. 绑定控制直接更新现有 StepEditorModel

普通界面不新增后端 API 或第二份状态。对可写的标准 click/doubleClick 步骤：

- 未绑定且存在 `current.evidence.reference` 时，“用于定位”将该安全的 task-relative 路径转换为单个 `ReviewReferenceImage`，写入 `editor.referenceImages`。
- 已绑定一张图片时，“取消使用”将 `editor.referenceImages` 设为空。
- 两种操作都调用现有语义草稿同步路径，使 `buildStepContent()` 在 `aiTap/aiDoubleClick` 简写和 `locate.prompt + locate.images` 结构之间转换。

操作只修改浏览器草稿，不立即写盘，因此不增加二次确认弹窗；用户仍通过“确认并写入”完成 canonical 保存，或者刷新页面放弃草稿。

### 3. 控制放在定位参考图卡片内，避免重复状态区

定位参考图页签内使用单一卡片组合图片、状态、功能说明和操作按钮：

- 未绑定：状态“可用，尚未用于定位”，按钮“用于定位”。
- 已绑定：状态“已用于执行定位”，按钮“取消使用”。
- builtin 或不支持的动作：保留图片与状态，禁用操作并展示原因。

现有表单下方的“有可用目标小图/已绑定执行参考图”摘要不再要求用户进入高级 JSON，避免同一状态在证据区和表单区重复表达。

### 4. 多图 YAML 进入兼容模式

底层 `ReviewReferenceImage[]` 和 Midscene `images` 数组保持不变。若已有 YAML 包含两张或更多定位参考图，页面完整展示和保留这些引用，但不提供单图绑定/取消使用按钮，并提示需要通过高级 JSON 维护。普通操作不得将多图静默压缩为一张。

该策略让新交互保持简单，同时避免破坏手工维护或未来版本生成的合法 Midscene 资产。

### 5. 操作资格由前端可推导状态决定

绑定控制只有在任务可写、当前步骤为可解析的标准 click/doubleClick、未处于高级 JSON 编辑或保存忙碌状态、且候选图片位于已由服务校验的任务 source 边界内时可用。其他状态只展示信息，不尝试在浏览器中重新解析任意文件路径。

## Risks / Trade-offs

- [“定位参考图”仍可能被理解为坐标截图] → 在卡片中固定展示“不表示固定点击坐标”的说明，不只依赖 tooltip。
- [取消使用会降低某些图标目标的定位稳定性] → 操作先进入可撤销草稿，并在变更对比中可见，最终仍需用户确认写入。
- [多图任务无法使用新的快捷按钮] → 明确进入兼容模式并无损保留；多图管理不在本轮范围内。
- [绑定后 Flow 的 JSON 结构变化较大] → 复用现有 step editor 构建与校验逻辑，并补充 bind/unbind 往返测试。
- [技术路径或图片名称从主界面移除后排障信息减少] → 高级 JSON 继续提供 canonical 名称和路径，普通界面聚焦语义操作。

## Migration Plan

无需数据迁移。既有未绑定录制图片会显示“用于定位”，已绑定单图会显示“取消使用”，多图 YAML 自动进入兼容模式。回滚前端不会改变已保存 YAML；已经通过按钮写入的 `locate.images` 仍是现有执行器支持的标准 Midscene 结构。

## Open Questions

无。本轮固定为单个录制候选图的绑定/取消使用，不引入文件选择、替换和多图管理。
